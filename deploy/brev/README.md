# Brev OliveTin Launcher

This folder contains a Brev-specific launcher for the Multi-Agent Intelligent
Warehouse blueprint. It uses OliveTin as a small operator dashboard for known
Brev machine assumptions: 4x H100 GPUs, local NIM, persistent data under
`/ephemeral/maiw`, and a single NVIDIA API key used for both app services and
`nvcr.io` image pulls.

## Layout

- `docker-compose.olivetin.yaml` runs the OliveTin dashboard on host port `9090`.
- `docker-compose.maiw.yaml` defines the blueprint services and local NIM stack.
- `config/config.yaml` defines OliveTin actions and dashboard layout.
- `config/custom-webui/custom.js` loads small browser-side OliveTin UI tweaks.
- `scripts/` contains action implementations.
- `.env` is generated by `Configure Blueprint` and must not be committed.
- `generated/docker-config/` stores Docker registry login state for OliveTin.

## Editing The Dashboard

Edit `config/config.yaml` to add, rename, or reorder actions. Actions are defined
under `actions:` and placed on the dashboard under `dashboards.contents`.
Dashboard links should bind to action IDs:

```yaml
- type: link
  title: Deploy Blueprint
  action:
    bindingId: deploy-blueprint
    canExec: true
    popupOnStart: execution-dialog
```

Use `popupOnStart: execution-dialog` for actions where the operator should see
logs while the command runs. Use `stdout-most-recent-execution` with the action
ID as `title` to show the latest status/output on the dashboard.

After edits:

```bash
cd deploy/brev
docker compose -f docker-compose.olivetin.yaml restart olivetin
```

OliveTin live-reloads some config changes, but restarting avoids stale browser
state while developing.

## Modifying Blueprint Configuration

`Configure Blueprint` runs `scripts/configure-blueprint.sh`. It writes
`deploy/brev/.env`, generates Postgres/JWT secrets when missing, and logs into
`nvcr.io` with:

```bash
docker login nvcr.io -u '$oauthtoken'
```

The NVIDIA API key field is a password argument and the action uses OliveTin
`exec`, so the key is passed via process environment instead of shell command
interpolation.

Account passwords are not stored in `.env`. Use the `Set Account Passwords`
dashboard action after demo data is installed. Blank password fields are ignored
so operators can update only one account at a time.

If adding more config inputs, add arguments to the `configure-blueprint` action
and update `scripts/configure-blueprint.sh`. Prefer narrow validators in the
script for secrets and `regex:` validators for non-secret IDs.

## Auto-Closing Execution Dialogs

OliveTin does not provide a built-in "close on success" flag. This folder enables
custom JavaScript with:

```yaml
enableCustomJs: true
```

`config/custom-webui/auto-close-dialog.js` listens for
`EventExecutionFinished`. For actions listed in `autoReturnActions`, it
redirects from `/logs/<executionTrackingId>` back to `/` after successful
completion. Failed actions stay on the log page so the operator can read the
error.

To add another auto-closing action, edit `autoReturnActions`:

```js
var autoReturnActions = {
  "configure-blueprint": true,
  "another-action-id": true
};
```

Restart OliveTin and refresh the browser after changing custom web UI files.
